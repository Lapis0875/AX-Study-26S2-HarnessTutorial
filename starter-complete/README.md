# 나만의 즐겨찾기 웹페이지 · 완료본

`starter/`와 같은 화면·입력·저장 기반에서 URL 중복 저장을 해결한 비교용 완료본입니다.
학생이 작업한 시작본을 덮어쓰지 않고 `starter-complete/`를 별도 폴더로 엽니다.

## 실행

Node.js **22.12.0 이상**과 npm이 필요합니다. 저장소 루트의 터미널에서 실행합니다.

```sh
cd starter-complete
npm ci
npm run dev
```

같은 컴퓨터의 브라우저에서 **http://127.0.0.1:5173**에 접속합니다.
서버 터미널을 유지하고, 종료할 때는 `Ctrl+C`를 누릅니다.
이미 `starter-complete/` 안에 있다면 `cd` 명령을 생략합니다.
5173 포트를 사용하는 시작본 서버를 종료한 후 완료본을 실행합니다.

## 해결한 동작

- 제목과 URL의 양끝 공백을 제거하고 필수 입력·http/https 절대 주소를 검증합니다.
- 저장한 URL 문자열과 완전히 같은 URL은 새 항목을 만들거나 저장하지 않습니다.
- 중복이면 **이미 저장된 웹주소입니다.**를 기존 처리 안내 영역에 표시합니다.
- 중복 시 두 입력값을 유지하고 웹주소 입력란으로 초점을 이동합니다. 기존 항목 이동·강조는 추가하지 않습니다.
- 기존 제목·URL·ID·순서를 보존합니다. 과거 중복도 자동 삭제·병합·숨김 처리하지 않습니다.
- 새로운 URL은 기존처럼 저장하고, 성공하면 입력란을 비우고 웹주소에 초점을 둡니다.

프로토콜·대소문자·포트·끝 슬래시·쿼리·fragment를 별도로 통합하지 않습니다.
예를 들어 `https://example.com/a`와 `https://example.com/a/`는 다른 문자열입니다.
제목은 중복 판단 기준이 아닙니다. 저장 과정에서 대상 사이트의 내용을 요청하지 않습니다.

## 시작본과 비교

1. **초기 예제로 되돌리기**를 누르고 영향 범위를 읽은 뒤 확인합니다.
2. 웹주소 `https://example.com/read-later/article-1`, 제목 `다시 읽을 글`을 제출합니다.
3. 목록은 1개이고 기존 제목 `주말에 읽을 글`이 유지되며 중복 안내가 표시됩니다.
4. 같은 주소를 다시 제출하거나 새로고침해도 새 중복이 생기지 않습니다.
5. 웹주소 `https://example.com/read-later/video-2`, 제목 `나중에 볼 영상`을 제출하면 2개가 됩니다.
6. 새로고침 후 두 항목과 제목·URL·ID·순서가 유지되는지 확인합니다.

예시 주소는 교육용 비교 문자열이며 실제 글·영상의 존재를 보장하지 않습니다.
저장 키는 시작본과 같은 `ax-study:l03:bookmarks:v1`입니다.
**같은 브라우저·같은 접속 주소에서 실행하면 시작본 자료를 그대로 읽습니다.**
코드 폴더를 바꾸는 것만으로 자료가 초기화되지 않습니다.
비교 전 기존 자료를 보존해야 한다면 초기화하지 말고 별도 브라우저 프로필을 사용합니다.
다중 탭 동시 편집·동기화는 범위 밖입니다.

## 검사

```sh
npm run test:baseline
npm run test:target
npm test
npm run build
```

완료본에서는 기본 검사, 목표 T01~T04, 추가 중복 회귀 검사가 모두 통과해야 합니다.
`npm test`는 세 검사 파일을 실행하며 성공 시 종료 코드 0입니다.
시작본의 T01·T03 예상 실패를 완료본의 정상 결과로 취급하지 않습니다.
목표 검사는 시작본과 동일한 기준을 사용합니다. 삭제하거나 건너뛰지 않습니다.
목록·중복 안내·입력 유지·초점·새 탭·새로고침·초기화는 브라우저에서도 확인합니다.
브라우저 자동화 도구는 학생 패키지의 필수 의존성이 아닙니다.

## 파일과 정책

`src/bookmarks.js`에서 입력 검증 후 ID 생성 전에 URL 중복을 확인합니다.
`controller.js`는 `added`일 때만 기록하므로 중복 제출은 저장 공간을 변경하지 않습니다.
`src/app.js`는 중복을 일반 성공·오류와 구분해 안내하고 입력을 유지합니다.
저장·읽기 실패 시 기존 자료와 입력을 보호하고, 손상·미지원 자료는 자동 초기화하지 않습니다.
명시적 초기화는 확인 후 수업용 키만 예시 한 개로 변경하며 취소·실패 시 기존 상태를 유지합니다.
