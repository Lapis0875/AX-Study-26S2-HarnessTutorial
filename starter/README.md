# 나만의 즐겨찾기 웹페이지 · 하네스 엔지니어링 실습 프로젝트

직접 입력한 제목과 웹주소를 저장하고 다시 열어 보는 로컬 실습 앱입니다.
같은 주소를 다시 추가하면 현재는 별도 항목이 생깁니다. 이번 실습에서 이 동작을 개선합니다.

## 실행 및 접속 가이드

처음에는 **준비 → 폴더 열기 → 설치 → 실행 → 브라우저 접속** 순서로 진행합니다.
명령은 브라우저 주소창이 아닌 **터미널**에 입력합니다. 터미널은 글자로 컴퓨터에 명령을 내리는 창입니다.
아래 명령은 한 줄씩 입력하고 `Enter`를 누르세요.

### 1. 준비하기

인터넷 연결, 웹브라우저, Node.js가 필요합니다. Node.js는 이 프로젝트의 실행 도구와 검사를 작동시키는 프로그램입니다.

Node.js를 설치하지 않았다면 [공식 다운로드 페이지](https://nodejs.org/en/download)에서 운영체제에 맞는 **LTS(장기 지원)** 설치 파일을 받습니다.
이 프로젝트는 **Node.js 22.12.0 이상**을 요구합니다. Node.js 설치 파일에는 npm도 포함됩니다.
설치 후에는 터미널과 코딩 도구를 닫았다가 다시 열어 주세요. 설치 방식은 [npm 공식 설치 안내](https://docs.npmjs.com/downloading-and-installing-node-js-and-npm/)에서도 확인할 수 있습니다.

터미널에서 다음 명령으로 설치 여부를 확인합니다.

```sh
node -v
npm -v
```

두 명령 모두 버전 번호가 나오면 준비된 상태입니다. 예를 들어 Node.js가 `v22.12.0`이면 최소 요구 버전을 충족합니다.
명령을 찾을 수 없다는 오류가 나오면 아래의 **실행이 안 될 때**를 확인하세요.

### 2. 프로젝트 폴더와 터미널 열기

강사가 제공한 ZIP을 **새 폴더**에 풀고, 그 안에서 `package.json`과 `package-lock.json`이 있는 **`starter` 폴더**를 찾습니다.
ZIP 내부에서 바로 실행하거나 기존 실습 폴더 위에 덮어쓰지 마세요.

선택한 코딩 도구의 **폴더 열기**로 `starter`를 연 다음, 도구 안에서 새 터미널을 엽니다.
코딩 도구 없이 운영체제의 터미널을 사용해도 됩니다.

| 환경 | `starter`에서 터미널을 여는 방법 |
| --- | --- |
| Windows | 파일 탐색기에서 `starter` 폴더를 연 뒤, 위쪽 주소 표시줄에 `cmd`를 입력하고 `Enter`를 누릅니다. |
| macOS | 터미널 앱을 열고 `cd `를 입력합니다. 공백 뒤에 Finder의 `starter` 폴더를 터미널로 끌어 놓고 `Enter`를 누릅니다. |

터미널이 프로젝트의 상위 폴더에서 열렸고 바로 아래에 `starter`가 있다면 다음 명령으로 이동합니다.
**이미 `starter` 안이라면 이 명령은 건너뜁니다.**

```sh
cd starter
```

Windows에서는 `dir`, macOS에서는 `ls`를 입력했을 때 `package.json`이 목록에 보이면 올바른 위치입니다.

### 3. 필요한 도구 설치하기 — 처음 한 번

`starter` 폴더의 터미널에서 실행합니다.

```sh
npm ci
```

이 명령은 함께 제공된 `package-lock.json`에 맞춰 필요한 도구를 내려받습니다.
설치 중에는 인터넷 연결이 필요하며, 완료되면 `node_modules` 폴더가 생깁니다.
터미널에 다시 명령을 입력할 수 있는 상태가 될 때까지 기다리세요. 설치가 오류로 끝났다면 다음 단계로 넘어가기 전에 해결합니다.

### 4. 로컬 서버 실행하기

같은 터미널에서 실행합니다.

```sh
npm run dev
```

정상 실행되면 출력 내용 중 다음 주소가 보입니다.

```text
Local: http://127.0.0.1:5173/
```

이제 터미널은 웹페이지를 제공하는 **로컬 서버**를 실행 중입니다.
명령 입력 대기 상태로 돌아오지 않는 것이 정상이며, 앱을 사용하는 동안 이 창을 열어 둡니다.

### 5. 브라우저에서 접속하고 확인하기

서버를 실행한 **같은 컴퓨터**의 브라우저 주소창에 아래 주소를 입력합니다.

**[http://127.0.0.1:5173](http://127.0.0.1:5173)**

`127.0.0.1`은 지금 사용하는 컴퓨터를 뜻합니다. 인터넷에 공개된 사이트 주소가 아닙니다.
`https://`가 아닌 `http://`를 사용하고, `index.html` 파일을 더블클릭해서 열지 않습니다.

화면에 **나만의 즐겨찾기 웹페이지**가 나타나면 접속에 성공한 것입니다.
처음 실행한 브라우저에서는 **주말에 읽을 글** 한 항목이 보입니다. 이전에 실습했다면 저장해 둔 목록이 보일 수 있습니다.

다음 값을 입력하고 **즐겨찾기 추가**를 눌러 보세요.

```text
웹주소: https://example.com/read-later/video-2
제목: 나중에 볼 영상
```

`저장했습니다.` 안내와 새 항목을 확인하고, 새로고침 후에도 항목이 남는지 확인합니다.
예시 주소는 교육용 문자열이므로 실제 영상 페이지가 존재한다는 뜻은 아닙니다.

### 6. 종료하고 다음에 다시 실행하기

서버를 실행한 터미널을 클릭한 뒤 **`Ctrl+C`**를 누르면 서버가 종료됩니다. macOS에서도 `Command`가 아닌 `Ctrl`입니다.
브라우저 탭만 닫으면 서버는 계속 실행됩니다.

다음에 사용할 때는 `starter`에서 터미널을 열고 **`npm run dev`**만 실행한 뒤 같은 주소로 접속합니다.
이미 설치했다면 매번 `npm ci`를 실행할 필요는 없습니다. 새 ZIP을 새 폴더에 풀었다면 설치 단계부터 진행합니다.

저장 자료는 **같은 브라우저·같은 접속 주소**에 남습니다. `localhost`와 `127.0.0.1`, 서로 다른 포트는 별도 저장 공간입니다.
서버를 종료하거나 코드를 새로 받아도 브라우저 자료가 자동으로 초기화되지는 않습니다.

### 실행이 안 될 때

| 증상 | 확인할 것 |
| --- | --- |
| `node` 또는 `npm` 명령을 찾을 수 없음 | Node.js 설치를 완료했는지 확인하고 터미널·코딩 도구를 다시 엽니다. |
| Node.js 버전 관련 오류 | `node -v`로 22.12.0 이상인지 확인합니다. |
| `package.json`을 찾을 수 없음 / `ENOENT` | 터미널의 현재 폴더를 확인합니다. `package.json`이 있는 `starter`에서 명령을 실행해야 합니다. |
| `vite`를 찾을 수 없음 | `starter`에서 `npm ci`가 성공했는지 확인합니다. |
| Windows PowerShell에서 `npm.ps1` 실행이 차단됨 | 위 표의 방법으로 명령 프롬프트(`cmd`)를 열어 같은 명령을 실행합니다. |
| 설치 중 다운로드·네트워크 오류 | 인터넷 연결을 확인합니다. 오류가 계속되면 오류 문구를 강사에게 전달합니다. |
| `Port 5173 is already in use` | 이전에 켜 둔 실습 서버가 있는지 확인합니다. 자신이 실행한 서버라면 해당 터미널에서 `Ctrl+C`로 종료한 뒤 다시 실행합니다. 모르는 프로세스는 종료하지 말고 문의합니다. |
| 브라우저에서 사이트에 연결할 수 없음 | 서버 터미널이 열려 있고 `Local:` 주소가 나왔는지, 주소가 `http://127.0.0.1:5173`인지 확인합니다. |
| `npm test`에서 두 검사가 실패함 | 시작본은 T01·T03 실패가 예상됩니다. 아래 **검사** 항목에서 실패 이름과 이유를 확인합니다. |

이 앱은 5173 포트가 사용 중이면 다른 포트로 자동 이동하지 않습니다.
해결이 어렵다면 **실행한 명령·오류 문구·접속 주소**를 함께 강사에게 전달하세요.

## 기술 스택

기술 스택은 프로젝트를 만드는 데 사용한 도구들의 조합입니다.

| 기술 | 이 프로젝트에서 맡은 역할 |
| --- | --- |
| HTML | 입력란, 버튼, 즐겨찾기 목록 등 화면의 구조를 만듭니다. |
| CSS | 색상·글자·간격과 모바일 화면 배치를 정합니다. |
| 일반 JavaScript 모듈 | 입력 확인, 항목 추가, 화면 갱신을 처리합니다. React 같은 별도 UI 프레임워크는 사용하지 않습니다. |
| Vite 8.3.1 | 개발 중 로컬 서버를 실행하고, 배포용 정적 파일을 만듭니다. |
| 브라우저 `localStorage` | 이 브라우저에 즐겨찾기를 저장하여 새로고침 후에도 불러옵니다. |
| Node.js 22.12.0 이상 | Vite와 자동 검사를 실행합니다. |
| npm · `package-lock.json` | 필요한 도구를 정해진 버전으로 설치합니다. |
| Node.js 내장 테스트 실행기 | 기본 기능과 개선 목표를 자동으로 검사합니다. |

즐겨찾기 기능은 브라우저에서 동작합니다. 별도 백엔드·서버 데이터베이스·로그인·AI API 연결은 필요하지 않습니다.
브라우저 자동화는 강사용 별도 도구이며 학생 앱의 설치 대상이 아닙니다.

## 폴더 구조와 파일 역할

실습에서 여는 폴더는 아래의 `starter/`입니다. 먼저 `docs/`로 작업을 이해하고, `src/`에서 동작을 읽은 뒤 `tests/`로 확인하면 됩니다.

```text
starter/
├── README.md                    # 실행·접속·실습 안내 (현재 문서)
├── package.json                 # 실행 명령과 필요한 도구 목록
├── package-lock.json            # 설치할 도구의 정확한 버전 기록
├── vite.config.js               # 로컬 서버 주소·포트·빌드 설정
├── index.html                   # 브라우저가 처음 읽는 화면 구조
├── src/                         # 앱의 실제 코드
│   ├── app.js                   # 버튼·폼 이벤트와 앱 동작 연결
│   ├── bookmarks.js             # 입력 검증과 새 항목 생성
│   ├── controller.js            # 추가·초기화 흐름과 현재 상태 관리
│   ├── storage.js               # 저장 자료 읽기·쓰기·초기화
│   ├── view.js                  # 목록·개수·안내·입력 오류 표시
│   └── styles.css               # 화면 스타일과 반응형 배치
├── docs/                        # 학생용 요청·근거·실습 자료
│   ├── current-behavior.md      # 현재 중복이 발생하는 동작
│   ├── requirements.md          # 개선 요구사항 R1~R4
│   ├── work-brief.md            # 강사 기준 요청서
│   ├── implementation-decisions.md # L03에서 채택한 정책
│   └── exercise.md              # 실습 진행 순서
├── fixtures/
│   └── bookmarks.json          # 초기 예시 한 항목의 JSON 자료
├── tests/
│   ├── baseline.test.js        # 기존 기본 기능 검사
│   ├── target.test.js          # 개선 목표 T01~T04 검사
│   └── helpers.js              # 검사에 쓰는 예시와 저장 공간 대역
└── public/
    └── robots.txt              # 검색 로봇용 정적 안내 파일
```

`node_modules/`는 설치할 때, `dist/`는 `npm run build`를 실행할 때 생깁니다.
둘 다 도구가 생성하는 폴더이므로 실습 코드는 `src/`에서 수정합니다.
`fixtures/bookmarks.json`은 예시 자료이며, 사용자가 추가한 즐겨찾기가 이 파일에 기록되지는 않습니다.
실제 저장 위치는 브라우저의 `localStorage`입니다.

**코드 흐름:** `index.html`이 `app.js`를 불러옵니다. 사용자가 추가 버튼을 누르면 `controller.js`가
`bookmarks.js`에서 다음 목록을 만들고 `storage.js`로 저장합니다. 저장에 성공하면 현재 상태를 바꾸고
`view.js`로 화면을 갱신합니다. 저장 실패 시에는 기존 목록과 입력값을 유지합니다.

## 제공 자료와 작업 순서

- [현재 동작](docs/current-behavior.md): U1 중복 재현
- [개선 요구사항](docs/requirements.md): R1~R4
- [강사 기준 요청서](docs/work-brief.md): L02 미완료자도 사용 가능
- [L03 결정 기록](docs/implementation-decisions.md): 입력·저장·화면·검사 계약
- [실습 순서](docs/exercise.md): 도구·자료·권한·검사 연결

작업 지침 양식은 **강의자료에서 안내**합니다. 배포 ZIP에는 `AGENTS.md`를 포함하지 않습니다.
강의자료의 양식을 자신의 작업에 맞게 작성한 뒤, 선택한 도구의 지침 파일이나 작업 요청에 반영하세요.
도구에 따라 지침 파일의 이름과 적용 방식이 다를 수 있으므로 실제로 읽혔는지 확인합니다.

자신의 L02 요청서를 사용하거나 강사 기준 요청서를 출발점으로 삼습니다. 제공받은 내용과 직접 수정한 내용을 구분하세요.

### 실습 전 확인할 기본 안내

- 기존 코드 변경과 저장된 제목·주소·ID를 보존합니다. 다른 실습 폴더에 덮어쓰지 않습니다.
- 실제 브라우저 즐겨찾기·개인 계정·비공개 자료를 읽거나 수정하지 않습니다.
- 기본·목표 검사와 실제 화면을 확인하고, 실행하지 않은 검사를 통과로 기록하지 않습니다.
- 지침 작성과 실제 권한 제한은 다릅니다. 사용하는 도구의 권한·승인 범위를 직접 확인합니다.

## 검사

```sh
npm run test:baseline
npm run test:target
npm test
npm run build
```

| 명령 | 시작본의 기대 결과 |
| --- | --- |
| `test:baseline` | 기본 기능 모두 통과 |
| `test:target` | T01/R1·T03/R3 실패, T02/R2·T04/R4 통과 |
| `npm test` | 기본·목표 검사를 함께 실행하므로 종료 코드 1 |
| `build` | 정적 앱 생성 성공 |

T01은 같은 주소 재입력 후 실제 저장 수가 1이어야 한다는 검사지만 현재 2가 됩니다.
T03은 `duplicate` 결과를 요구하지만 현재 `added`입니다. 이 두 실패가 실습 출발점입니다.
설치 오류, 문법 오류, 다른 실패를 예상 실패로 취급하지 마세요. 검사를 삭제하거나 건너뛰어 통과시키지 않습니다.
개선 후에는 같은 목표 검사 네 개가 모두 통과하고 기본 검사도 계속 통과해야 합니다.

자동 검사는 로직을 확인합니다. 목록·안내·초점·새 탭·새로고침은 브라우저에서도 확인하세요.
학생 설치에는 브라우저 자동화 도구가 포함되지 않습니다.

## 처음 상태로 돌아가기

화면의 **초기 예제로 되돌리기**를 누르고 영향 범위를 읽은 뒤 확인하면 수업용 데이터만 예시 한 개로 돌아갑니다.
취소하면 현재 상태를 유지합니다. 정상적인 빈 목록은 새로고침해도 빈 목록으로 유지됩니다.
저장·읽기 실패 시 성공으로 처리하지 않습니다. 읽기 실패 상태에서는 추가가 중단됩니다.
자료를 보존해야 한다면 초기화 전에 강사에게 문의하세요. 브라우저 전체 데이터를 지우지 않습니다.
