# 작은 변경을 실행하고 확인하기

1. ZIP을 새 폴더에 풀고 앱 루트를 코딩 도구에서 엽니다.
2. 자신의 L02 요청서 또는 `work-brief.md`와 근거 문서를 도구가 읽게 합니다. 이해한 작업 범위를 확인합니다.
3. 강의자료에서 안내하는 작업 지침 양식에 바꿀 동작·제외 범위·검사·보고 방식을 직접 작성합니다. 선택한 도구의 지침 파일이나 작업 요청에 반영합니다. 배포 ZIP에는 `AGENTS.md`가 포함되지 않습니다.
4. 도구의 권한·승인 설정을 확인합니다. 지침 파일 자동 적용 여부를 확인하고 수동으로 읽혔다면 수동 적용이라고 기록합니다.
5. 앱과 기본·목표 검사를 실행합니다. 현재 U1 1→2와 T01·T03 실패 이유를 확인합니다.
6. R1~R4에 해당하는 작은 변경을 요청하고 코드를 확인합니다.
7. 같은 검사와 브라우저 행동을 다시 실행합니다. 기존 자료가 바뀌지 않았는지 확인합니다.
8. 구현한 것, 실행한 검사, 미실행 항목과 남은 문제를 구분해 기록합니다.

## 브라우저 확인 순서

명시적으로 초기화 → U1을 `다시 읽을 글` 제목으로 추가 → 개수·두 제목·안내 확인 → 새로고침.
개선 후에는 개수가 늘지 않고 기존 제목이 유지되며 중복 안내가 있어야 합니다.
초기화 후 U2 `https://example.com/read-later/video-2`를 `나중에 볼 영상`으로 추가하면 2개가 되어야 합니다.
링크가 새 탭으로 열리는지 확인하되 예시 사이트의 글·영상 존재 여부를 합격 기준으로 삼지 않습니다.

필수·잘못된 주소 입력의 오류와 입력 유지, 초기화 취소도 확인합니다.
저장 오류를 만들려고 자신의 실제 자료를 손상시키거나 브라우저 전체 데이터를 지우지 않습니다.
강사가 제공한 오류 검수 결과를 참고하거나 개별 문의합니다.

도구는 자유롭게 선택합니다. 유료 AI API 연결은 필요 없습니다.
L02 미완료자도 기준 요청서로 참여할 수 있습니다. 당일 전원 완료나 별도 필수 복습 제출을 요구하는 안내가 아닙니다.
